# experiments — IMU 직진 유지 실험

캐스터(앞바퀴)가 매번 다른 방향으로 틀어져 있어서, 조이스틱을 정확히 앞으로 밀어도
휠체어가 휘어 나간다. 이 폴더는 그 문제만 따로 떼어내 IMU(MPU6050)로 잡는 실험이다.
카메라/YOLO를 안 쓰므로 3초면 뜨고, 시리얼만 있으면 돌아간다.

```bash
cd src/v2_vision/jetson_nano
python3 experiments/straight_drive.py
```

## 조작

시작하면 IMU yaw 캘리브레이션이 자동으로 돈다(자이로 0점 잡기). **그 몇 초 동안만
휠체어를 가만히** 두면 되고, 그 뒤로는 아래 키가 전부다.

| 키 | 동작 |
|---|---|
| `W` / `S` | 전진 / 후진 (방위각을 유지하며 간다) |
| `A` / `D` | 좌 / 우회전 — 의도된 회전이므로 보정하지 않음 |
| `SPACE` | 정지 |
| `I` | **기준 방위각 고정 / 해제** |
| `Q` | 종료 (조이스틱 중립 복귀 후) |

기준 방위각(= 맞추려는 방향)은 두 가지 방식으로 정해진다.

- **평소**: `W`/`S`를 누른 그 순간의 방위각. 그 구간 동안 그 방향을 유지한다.
  `A`/`D`로 돌리면 기준이 사라지고, 다시 `W`를 누르면 새 방향으로 잡힌다.
- **`I`로 고정했을 때**: 그 순간의 방위각을 못박는다. 이후 `A`/`D`로 아무리 돌려놓아도
  `W`를 누르면 **무조건 그 방위각으로 되돌아온다**(50° 벗어난 상태에서 약 7초).
  다시 `I`를 누르면 해제.

보정 ON/OFF·부호·yaw 켜기는 전부 자동이라 누를 키가 없다.

## 원리

### 무엇을 재고 무엇을 움직이나

- **잰다**: ESP32가 보내주는 `yaw`(누적 방위각, °)와 `gyro_z`(회전 각속도, °/s).
- **움직인다**: 조이스틱을 물고 있는 서보 2축. `x`가 좌우(조향), `y`가 전후(속도).
- **부호 규약(실측)**: 서보 `x`를 중립 87보다 **키우면 왼쪽**, 그때 `yaw`가 증가하고
  `gyro_z`가 양수. **전진/후진 모두 같다** (아래 "후진 부호" 절 참고).

보정은 **`x`(조향)만 건드린다.** `y`(전후 속도)는 프리셋 그대로 둔다.

### 왜 캘리브레이션이 아니라 피드백인가

캐스터가 어느 쪽으로 틀어지는지는 직전에 어떻게 움직였느냐에 따라 매번 달라진다
(실측 -1.6 ~ +4.9°/s, 방향도 뒤집힌다). 미리 "이만큼 틀어지니 이만큼 상쇄" 하는
상수를 구해둘 수가 없다. 그래서 **매 순간 실제로 얼마나 돌고 있는지를 재서 그만큼
되받아치는** 폐루프로 간다. 틀어짐의 패턴을 몰라도 되는 게 이 방식의 핵심이다.

### 제어식

이동 중(`W`/`S`)일 때 매 루프(~33Hz) 아래를 계산한다.

```
yaw_err  = yaw - yaw0                            # 기준에서 얼마나 벗어났나 (°)

# ① 방위 오차 → 목표 회전속도 (°/s)
rate_tgt = 0                    if |yaw_err| <= 1.0      (데드밴드)
         = -yaw_err / 1.5       그 밖에                   (CORR_TAU=1.5초)
rate_tgt = clamp(rate_tgt, ±10)                          (CORR_RATE_MAX)

# ② 목표 회전속도 vs 실제 회전속도 → 조향량
rate_err = rate_tgt - gyro_z
bias    += 0.8 * rate_err * dt                           (CORR_KI, ±13 제한)
u        = 0.4 * rate_err + bias                         (CORR_KR)

# ③ 데드존 보상
comp     = 4.0 * min(|u| / 1.5, 1)                       (CORR_DEADZONE / KNEE)
corr_x   = clamp(u + sign(u) * comp, ±13)                (CORR_MAX_DEG)

서보 x 목표 = 87 + corr_x     (램프가 83°/s로 접근)
```

**① 오차를 "속도 목표"로 바꾸는 이유.** 오차에 비례해 서보를 꺾는 단순 P제어는 반드시
좌우로 진동한다. 오차가 0이 되는 순간에도 휠체어는 관성으로 계속 돌고 있어서 반대편으로
넘어가고, 그러면 또 반대로 꺾기 때문이다. 실측으로 잡힌 장면이 이것이다 —
**오차 +1.2°(거의 복구)인데 자이로는 -17.7°/s**(맹렬히 돌아가는 중).
목표를 "각도"가 아니라 "지금 내야 할 회전속도"로 두면, 오차가 줄수록 목표 속도도
같이 줄어서 **스스로 감속**한다. 1.5초에 걸쳐 되돌리는 완만한 값이라 급하게 꺾지 않는다.

**② 자이로가 브레이크다.** 목표 회전속도와 실제 회전속도의 차이로 조향량을 정하므로,
이미 그쪽으로 충분히 돌고 있으면 더 밀지 않는다. 진동이 사라지는 지점이 여기다.

**② 적분항(`bias`)이 틀어짐을 학습한다.** 캐스터가 만드는 틀어짐은 한 구간 동안은
거의 일정하다. 그걸 이기려면 조향을 **계속** 물고 있어야 하는데, 비례항만으로는
오차가 남아야 힘이 나오므로 결국 **비뚤어진 채로 평행하게 가버린다**(시뮬에서 6°에
멈춤). 적분항이 "이 캐스터를 이기는 데 필요한 편향"을 주행 중 쌓아 물고 있어서
오차가 0으로 수렴한다. 화면의 `(학습 -5.2°)`가 이 값이다.

**③ 데드존 보상.** 조이스틱은 작게 밀면 아예 안 먹는다 — 실측으로 **편향 4.5°는
0.9초 동안 yaw가 한 자리도 안 변했고, 13°에서 갑자기 -18°/s**가 나왔다. 그래서 최소
편향을 얹어 반응하는 구간까지 끌어올린다. 단, 계단식으로 얹으면 `u`가 0을 지날 때
좌↔우로 튀므로 `|u|`가 1.5에 이를 때까지 서서히 얹는다.

### 통신 끊김 대비

ESP32 텔레메트리는 **평균 3Hz, 최대 1.01초 공백**이다. 그 사이 같은 값이 계속 오므로
"새 값인지"를 구분해야 한다(`yaw != 직전 yaw`). 두 곳에 쓴다.

- **적분 정지** — 새 값이 0.45초 넘게 안 오면 `bias`를 쌓지 않는다. 눈 감고 쌓으면 폭주.
- **보정 페이드** — 같은 조건에서 `corr_x`를 0.4초에 걸쳐 0으로 뺀다. 안 그러면
  1초 공백 동안 최대로 밀어서 8°가 그냥 넘어간다.

### 기준 방위각을 "새 값"으로 잡는 이유

키를 누른 순간의 `yaw`는 최대 1초 묵은 값이다. 그대로 기준으로 삼으면 시작하자마자
없는 오차가 생긴다(실측 +1.8°). 그래서 키를 누르면 바로 잡지 않고 **새 샘플이 오고
직전 회전이 잦아든 뒤**(|gyro_z| < 4°/s, 최대 1.2초 대기) 잡는다. 화면에
`기준 방위각 잡는 중...`이 잠깐 뜨는 게 이 구간이다.

`W`/`S`를 연타해도 기준은 다시 잡지 않는다(누적된 오차를 용서하게 되므로).
상태가 실제로 바뀔 때만 잡는다.

### 안전 장치

- **전방 30cm 미만이면 자동 정지** (전진 중에만). 단 초음파 전원이 꺼져 있으면 무력.
- **기준에서 30° 넘게 벗어나면 자동 정지.** 보정만 놓으면 휠체어가 비뚤어진 채로
  계속 간다(실측: 12초 동안 78°까지). 그만큼 벗어났다는 건 뭔가 잘못됐다는 뜻이다.
  `I`로 고정한 상태에선 `A`/`D`로 돌린 뒤라 크게 벌어진 채 출발하는 게 정상이므로,
  절대값이 아니라 **"출발할 때보다 30° 더 벌어졌는가"** 로 판단한다.
- **어떤 경로로 끝나든 조이스틱 중립 복귀** (`Q`, Ctrl-C, 예외 전부).
- 서보는 한 번에 튀지 않고 **83°/s로 램프**되어 접근한다(브라운아웃 방지).

## 상수

`straight_drive.py` 상단. 튜닝값은 실측 로그로 만든 플랜트 모델에 게인 스윕을 돌려
골랐고, 조향 권한이 실측의 절반~2배로 변해도 견디는 값이다.

| 상수 | 값 | 뜻 |
|---|---|---|
| `CORR_TAU` | 1.5초 | 방위 오차를 이 시간에 걸쳐 되돌린다 (작을수록 공격적) |
| `CORR_RATE_MAX` | 10°/s | 목표 회전속도 상한. 평소엔 3~5°/s만 쓰고, 고정 방위각 복귀에서만 여기까지 |
| `CORR_KR` | 0.4 | 회전속도 오차 1°/s당 서보 x |
| `CORR_KI` | 0.8 | 틀어짐 학습 속도 |
| `CORR_DEADZONE` / `KNEE` | 4.0 / 1.5 | 데드존 보상량 / 서서히 얹는 구간 |
| `CORR_MAX_DEG` | 13° | 보정 상한 (= 풀 회전 수준) |
| `CORR_DEADBAND_DEG` | 1.0° | 이 안쪽이면 되돌리지 않고 회전속도 0 유지만 |
| `CORR_STALE_S` / `FADE_S` | 0.45 / 0.4초 | 끊김 판정 / 보정을 빼는 시간 |
| `CORR_ABORT_DEG` | 30° | 이만큼 더 벌어지면 자동 정지 |
| `REF_SETTLE_RATE` / `MAX_WAIT` | 4°/s / 1.2초 | 기준 방위각을 잡는 조건 |

## 한 번 틀렸던 것 — 후진 부호

"후진에선 조향이 반대"라고 믿고 후진에만 부호 반전을 넣었던 시기가 있었다. **틀렸다.**
전 로그에서 서보 편향 방향과 실제 yaw 변화를 대조해보면 전진/후진 모두 x+(좌) →
yaw 증가로 같다 (후진 +11.2° 편향에 +14.2°/s). 반전을 넣었던 건 그때 전역 부호가
반대여서 우연히 맞아 보였던 것이고, 전역 부호를 고친 뒤에도 반전이 남아 후진만
이중으로 뒤집혀 폭주했다 (110532 로그: 왼쪽으로 치우쳤는데 왼쪽 최대로 밀어 8°→31°).

자이로로 실제 회전을 재서 맞추는 구조에선 방향별 반전이 애초에 필요 없다.
부호가 의심되면 감으로 뒤집지 말고 로그에서 `cmd_x`와 `yaw` 변화를 대조할 것.

## 기록

`experiments/logs/drive_<시각>.csv` (10Hz, 1초마다 flush — 강제종료해도 남는다).
`logs/`는 `.gitignore` 처리되어 있다.

분석에 중요한 열:

- `yaw_err` — 기준 방위각에서 얼마나 벗어났나 (이게 작게 유지되면 성공)
- `rate_tgt` vs `gyro_z` — 목표 회전속도를 실제로 따라가고 있나
- `bias` — 캐스터 틀어짐을 얼마나 학습해서 물고 있나
- `corr_x` / `cmd_x` — 보정량과 실제 서보 명령 (중립 87 기준)
- `lock` — `I`로 기준을 고정한 상태였나
- `echo_x` / `echo_y` — ESP32가 되돌려준 실제 서보 위치 (명령이 먹었는지 확인용)

## 남은 문제

- **텔레메트리 3Hz가 병목이다.** 초음파 4~5개를 순서대로 재느라(각 최대 38ms
  타임아웃) 느려지는 것으로 보인다. 펌웨어에서 **IMU(yaw/gyro)만 따로 20Hz로**
  쏘게 하면 보정 품질이 확 올라간다. 지금 게인은 3Hz를 견디도록 보수적으로 잡혀 있다.
- **측면 초음파 4개가 전부 -1**(전방은 정상). 센서군 전원/배선 확인 필요.
- **`ultrasound/sample.ino`가 실제 플래시된 펌웨어와 다르다.** 실제 펌웨어에는
  MPU6050 코드(`imu_ready`/`yaw`/`gyro_z`/`yaw_toggle`)가 들어 있는데 저장소 버전에는
  없다. 실제 .ino를 커밋해야 한다.
