# experiments — IMU 직진 유지 실험

캐스터(앞바퀴)가 매번 다른 방향으로 틀어져 있어서 전/후진 명령을 줘도 휠체어가
휘어 나간다. 이 폴더는 그 문제만 따로 떼어내 IMU(MPU6050)로 잡는 실험이다.
카메라/YOLO를 안 쓰므로 3초면 뜨고, 시리얼만 있으면 돌아간다.

```bash
cd src/v2_vision/jetson_nano
python3 experiments/straight_drive.py
```

## 조작

시작하면 IMU yaw 캘리브레이션이 자동으로 돈다. **그 몇 초 동안만 휠체어를 가만히**
두면 되고, 그 뒤로는 아래 키가 전부다.

| 키 | 동작 |
|---|---|
| `W` / `S` | 전진 / 후진 (누른 순간의 방위각을 유지하며 간다) |
| `A` / `D` | 좌 / 우회전 — 의도된 회전이므로 보정하지 않음 |
| `SPACE` | 정지 |
| `I` | **기준 방위각 고정/해제** |
| `Q` | 종료 (조이스틱 중립 복귀 후) |

`I`를 누르면 그 순간의 방위각을 못박는다. 이후 `A`/`D`로 아무리 돌려놓아도 `W`를
누르면 **무조건 그 방위각으로 되돌아온다**(50° 벗어난 상태에서 약 7초). 다시 누르면
해제되고, 원래대로 `W`/`S`를 누른 방향을 유지한다.

보정 ON/OFF·부호·yaw 켜기는 전부 자동이라 누를 키가 없다.

## 제어 구조

방위 오차만 보고 서보를 꺾는 단순 P제어는 **좌우 진동**을 일으켰다. 오차가 0이 되는
순간에도 휠체어는 관성으로 계속 돌고 있어서 반대편으로 넘어가고, 그러면 또 반대로
꺾기 때문이다 (실측: 오차 +1.2°인데 자이로 -17.7°/s). 그래서 3중 구조로 바꿨다.

1. **방위 오차 → 목표 회전속도** — `CORR_TAU`(1.5초)에 걸쳐 되돌리는 완만한 값.
   오차가 줄면 목표 속도도 같이 줄어드니 저절로 감속한다.
2. **목표 회전속도 vs 자이로 실측 → 서보 편향** — 자이로가 브레이크 역할을 한다.
3. **적분항** — "지금 이 캐스터를 이기는 데 필요한 편향"을 주행 중 학습해서 물고
   있는다. 틀어짐의 패턴을 몰라도, 매번 달라져도 수렴하는 이유가 이것이다.

여기에 실측에서 나온 세 가지 보정을 얹었다.

- **데드존 보상** — 편향 4.5°는 0.9초간 완전 무반응이었고 13°에서 갑자기 -18°/s가
  나왔다. 작은 보정이 아예 안 먹으므로 최소 편향을 얹되, 계단식으로 얹으면 0을 지날
  때 좌↔우로 튀어서 `CORR_COMP_KNEE` 구간에서 서서히 얹는다.
- **끊김 대비** — 텔레메트리가 평균 3Hz(최대 1초 공백)라, 그 사이 눈 감고 최대로
  밀면 8°가 그냥 넘어간다. 새 값이 안 오면(`CORR_STALE_S`) 보정을 놓는다.
- **기준 방위각 신선도** — 키를 누른 순간의 yaw는 최대 1초 묵은 값이다. 그대로 쓰면
  시작부터 유령 오차(+1.8° 실측)가 생기므로, 새 샘플이 오고 직전 회전이 잦아든 뒤에
  잡는다.

## 실측값 (2026-08-25)

| 항목 | 값 | 비고 |
|---|---|---|
| 조이스틱 중립 | X 87, Y 85 | 90/90이 아님 |
| 전/후진 편향 | 전진 Y 40, 후진 Y 30 | `hardware/esp32.py` |
| 좌/우 편향 | 좌 13, 우 15 | 풀 회전 |
| 조향 데드존 | 편향 4.5° 무반응, 13°에서 -18°/s | 매우 비선형 |
| 캐스터 드리프트 | -1.6 ~ +4.9°/s | 방향은 직전 움직임에 따라 바뀜 |
| IMU 정지 드리프트 | 12초에 0.000° | 펌웨어 deadband |
| 텔레메트리 주기 | 평균 3Hz, 중앙값 0.25s, **최대 1.01s** | 병목 |
| 부호 규약 | 서보 X + (좌) → yaw 증가, gyro_z 양수 | **전진/후진 동일** |

튜닝 상수는 위 실측으로 만든 플랜트 모델에 게인 스윕을 돌려 골랐다
(`CORR_KR` 0.4, `CORR_KI` 0.8, 데드존 보상 4.0, `CORR_TAU` 1.5). 권한이 실측의
절반~2배로 변해도 견디는 값이다.

## 기록

`experiments/logs/drive_<시각>.csv` (10Hz, 1초마다 flush — 강제종료해도 남는다).
`logs/`는 `.gitignore` 처리되어 있다.

분석에 중요한 열:

- `yaw_err` — 기준 방위각에서 얼마나 벗어났나 (이게 작게 유지되면 성공)
- `rate_tgt` vs `gyro_z` — 목표 회전속도를 실제로 따라가고 있나
- `bias` — 캐스터 틀어짐을 얼마나 학습해서 물고 있나
- `corr_x` / `cmd_x` — 보정량과 실제 서보 명령 (중립 87 기준)

## 한 번 틀렸던 것 — 후진 부호

"후진에선 조향이 반대"라고 믿고 후진에만 부호 반전을 넣었던 시기가 있었다. **틀렸다.**
전 로그에서 서보 편향 방향과 실제 yaw 변화를 대조해보면 전진/후진 모두 X+(좌) →
yaw 증가로 같다 (후진 +11.2° 편향에 +14.2°/s). 반전을 넣었던 건 그때 전역 부호가
반대여서 우연히 맞아 보였던 것이고, 전역 부호를 고친 뒤에도 반전이 남아 후진만
이중으로 뒤집혀 폭주했다(110532 로그: 틀어진 쪽으로 더 밀어 8°→31°).

자이로로 실제 회전을 재서 맞추는 구조에선 방향별 반전이 애초에 필요 없다.
부호가 의심되면 감으로 뒤집지 말고 로그에서 `cmd_x`와 `yaw` 변화를 대조할 것.

## 남은 문제

- **텔레메트리 3Hz가 병목이다.** 초음파 4~5개를 순서대로 재느라(각 최대 38ms
  타임아웃) 느려지는 것으로 보인다. 펌웨어에서 **IMU(yaw/gyro)만 따로 20Hz로**
  쏘게 하면 보정 품질이 확 올라간다. 지금 게인은 3Hz를 견디도록 보수적으로 잡혀 있다.
- **측면 초음파 4개가 전부 -1**(전방은 정상). 센서군 전원/배선 확인 필요.
- **`ultrasound/sample.ino`가 실제 플래시된 펌웨어와 다르다.** 실제 펌웨어에는
  MPU6050 코드(`imu_ready`/`yaw`/`gyro_z`/`yaw_toggle`)가 들어 있는데 저장소 버전에는
  없다. 실제 .ino를 커밋해야 한다.
