# V3 — UWB 측위

휠체어 위치를 카메라 대신 **UWB 거리 측정**으로 구한다. 차에 앵커를 달고 휠체어에 태그를 단다.
시야에 기대지 않으니 V1·V2의 막힌 곳 상당수가 함께 사라진다는 가정에서 출발한다.
이 폴더는 그 가정을 **측정으로 확인하는 것**부터 시작한다.

원리(무엇을 재나, 높이 차이, 오차 원인, 맥북의 역할)는 [UWB_원리_정리.md](UWB_원리_정리.md).

> 2026-10-29 착수. 보드 4개 구매, 펌웨어·기록 도구·실시간 화면 작성. 앵커 1 + 태그 1로 거리가 나오는 것까지 확인
> (가까이 둔 상태에서 8초간 79/79 성공, 표준편차 1.8 cm). 줄자와 비교한 정확도 실험은 아직이다.

## 왜 UWB인가

V1·V2 문제점 원본은 발표자료에 있다 — `files/휠체어자동주차_0901.pptx` 2~3쪽(V1·V2),
`휠체어자동주차_0821.pptx` 3~11쪽(9단계별). 정리본은 [설계 노트](../../docs/DESIGN.md)의 "단계마다 남은 문제".

| 막힌 곳 | 원인 | UWB에서 |
|---|---|---|
| V1 렌즈 주변부 왜곡, 가시영역 제한 | 카메라 시야 | 시야가 필요 없다 |
| V2 카메라·초음파가 놓치면 위치를 모름 | 특징이 보여야 측위 | 항상 좌표가 나온다. 단, **차체에 가렸을 때**는 실측 필요 |
| V2 휠체어에 하드웨어가 너무 많음 | Jetson·카메라·초음파·ESP32 | 태그 보드의 ESP32에 IMU를 직접 붙이면 보드 하나로 줄 수 있다 |
| 1단계 IBVS 진동 · 2단계 x축 오차 | 화면 특징 매칭 | 좌표로 정렬 |
| 4단계 70° 고정값 | 위치를 모르고 회전 | 현재 좌표에서 회전각 계산 |
| 3·5·8단계 캐스터로 휨 | 바퀴 상태 관측 불가 | **직접 해결은 아니다.** 위치 피드백으로 경로를 다시 따라간다 (V1 `08_parking` planner·tracker 방식) |
| 6단계 후방 정렬 불일치 | 초음파 배치 | ±10 cm가 트렁크·경사로 정렬에 충분한지 실측 필요 |

## 하드웨어

**ESP32 UWB DW3000** (Makerfabs 호환품, 빨간 PCB) × 4

| 부품 | 내용 |
|---|---|
| MCU | ESP32-WROOM-32E (ESP32-D0WD-V3) |
| UWB | "UWB-X3" DW3000 모듈. 칩 ID `deca0302` = **DW3000 C0, PDoA 없음** (단일 안테나 → 거리만, 각도 없음) |
| USB | CP2104 USB-UART. 맥 기본 드라이버(AppleUSBSLCOM)로 잡힌다. 포트 이름 끝이 칩 고유번호 |
| 전원 | micro USB 5 V (4.8~5.5 V). 차·휠체어에 달 때는 USB 보조배터리가 가장 간단 |

### 핀 — 기판 안에서 이미 연결됨

| DW3000 | ESP32 |
|---|---|
| RST / IRQ / CS | 27 / 34 / 4 |
| SPI SCK / MISO / MOSI | 18 / 19 / 23 |

나머지 헤더 핀은 ESP32의 남는 GPIO다. 나중에 IMU 등을 붙일 때 위 6개는 피한다.
**V2 `ultrasound/sample.ino`의 핀 배치(18·19·23·27·34 사용)는 그대로 옮길 수 없다.**

### `XTRIM OTP READ FAIL`

부팅 때마다 나오는 경고. 호환 모듈이라 DW3000 내부 메모리에 수정발진기 보정값이 비어 있고,
라이브러리가 기본값(`0x2E`)으로 채운다. 두 보드의 시계 차이는 측정할 때마다 반송파로 보정하므로
측정이 안 되는 문제는 아니다. 거리가 일정하게 어긋나면 안테나 지연과 함께 본다.

### 보드 목록

라벨 = 고유번호 끝 4자리. 보드에 스티커로 붙여 둔다.

| 라벨 | 고유번호 | ESP32 MAC | 역할 | 상태 (2026-10-29) |
|---|---|---|---|---|
| DFCA | 030ADFCA | d8:bf:c0:86:c7:7c | 태그 | `uwb_tag` 업로드, 정상 동작 |
| DFBB | 030ADFBB | d8:bf:c0:84:f3:b4 | 앵커 | `uwb_anchor` 업로드 (115200), 정상 동작 |
| | | | | 미점검 |
| | | | | 미점검 |

### 맥에서 포트가 멈추는 문제

두 보드 모두 겪었다 (2026-10-29). 보드 불량이 아니라 **맥 기본 CP2104 드라이버(AppleUSBSLCOM)** 쪽으로 본다.

| 증상 | 겪은 보드 |
|---|---|
| USB 장치로는 잡히는데 `/dev/cu.usbserial-*`가 안 생김 | DFBB |
| 포트를 열면 `termios.error: (22, 'Invalid argument')` | DFBB, 그다음 DFCA |
| 열린 채로 데이터가 끊김 — 보드는 멀쩡히 동작 중 (앵커는 계속 응답) | DFCA |
| 921600 업로드가 `The chip stopped responding`으로 중간에 끊김 | DFBB |

- 근거: DFCA는 세션 내내 뽑지 않아 드라이버 인스턴스가 처음 그대로였고, USB 재연결 기록은 없었다
  (전원이 흔들려 보드가 다시 잡힌 게 아님). 다시 꽂은 DFBB는 새 인스턴스로 정상
- **해결: 그 보드를 뽑았다 다시 꽂는다.** 업로드는 115200으로 (아래)
- 자주 반복되면 Silicon Labs 공식 CP210x 드라이버 설치를 검토 (아직 안 해 봄)
- `live_view.py`는 태그 데이터가 3초 넘게 끊기면 카드를 '연결 문제'로 바꿔 알려 준다

## 폴더

```
v3_uwb/
├── UWB_원리_정리.md    TWR 원리 · 높이 차이 · 오차 원인 · 설정값의 뜻
├── firmware/
│   ├── uwb_anchor/     SS-TWR 응답자 — 차에 다는 쪽. 전원만 있으면 됨
│   └── uwb_tag/        SS-TWR 개시자 — 휠체어 쪽. 거리·진단값을 CSV 한 줄로 출력
├── tools/
│   ├── uwb_proto.py      보드 연결 · 출력 형식 · dBm 환산 (공용)
│   ├── live_view.py      실시간 웹 화면 서버 — 보드별 카드, 기록, 포트 놓기
│   ├── live_view.html    그 화면 (서버가 요청마다 읽으므로 고치고 새로고침만 하면 됨)
│   ├── check_board.py    연결된 보드 점검 (칩 ID · 올라간 펌웨어)
│   ├── log_range.py      거리 측정 기록 → data/range/ (터미널용)
│   └── analyze_range.py  정확도 표 · 안테나 지연 추정
└── data/range/         측정 CSV (실험 근거라 git에 남긴다. 300개 ≈ 20 KB)
```

펌웨어는 Makerfabs 예제(`range_tx` / `range_rx`, 원본은 Qorvo ex_06a/b)에서 출발했다.
바꾼 것은 각 `.ino` 머리말에 적었다. 요약하면 출력 형식(CSV), 실패 기록, 수신 진단값, 10 Hz.

## 준비 (한 번만)

1. **라이브러리** — [Makerfabs-ESP32-UWB-DW3000](https://github.com/Makerfabs/Makerfabs-ESP32-UWB-DW3000)
   (커밋 `9d449b8`, 2026-07-01에서 확인)의 `Dw3000` 폴더를 `~/Documents/Arduino/libraries/`에 복사
2. **보드** — Arduino IDE 보드 매니저의 **esp32 (Espressif)** 2.0.17 → `ESP32 Dev Module`.
   "Arduino ESP32"는 다른 패키지라 고르지 않는다. 예제는 2.0.16 기준, 3.x는 확인 안 함
3. **Python** — `pyserial`

## 업로드

Arduino IDE에서 `.ino`를 열고 보드·포트를 고른 뒤 업로드하면 된다. 터미널에서는 IDE에 들어 있는 arduino-cli를 쓴다.

```bash
CLI="/Applications/Arduino IDE.app/Contents/Resources/app/lib/backend/resources/arduino-cli"
cd src/v3_uwb/firmware
"$CLI" compile --fqbn esp32:esp32:esp32 --upload -p /dev/cu.usbserial-030ADFCA uwb_tag
"$CLI" compile --fqbn esp32:esp32:esp32 --upload -p /dev/cu.usbserial-030ADFBB uwb_anchor
```

자동 리셋 회로가 있어서 FLASH 버튼은 누르지 않아도 됐다. "Connecting..."에서 멈추면 그때 누른 채로 다시.

업로드 도중 `The chip stopped responding`으로 끊기면 속도를 낮춘다 (DFBB가 그랬다. 반쯤 써진 채로 두면 부팅이 안 된다.
위 "맥에서 포트가 멈추는 문제"와 같은 원인일 수 있다).
IDE에서는 도구 → Upload Speed → 115200, 터미널에서는 `--fqbn esp32:esp32:esp32:UploadSpeed=115200`.
**앵커와 태그의 `TX_ANT_DLY`·`RX_ANT_DLY`·지연 상수는 짝이 맞아야 한다.**

## 사용

### 실시간 웹 화면 (기본)

```bash
cd src/v3_uwb
python3 tools/live_view.py     # http://localhost:8765 가 자동으로 열린다
```

꽂혀 있는 보드를 전부 찾아 보드마다 카드를 띄운다. 새로 꽂은 보드는 2초 안에 나타난다.

| 카드 | 보이는 것 |
|---|---|
| 태그 | 현재 거리 · 평균±표준편차 · 성공률 · 측정 속도 · RX−FP · 최근 30초 그래프(실패는 ×) · 최근 측정 표 |
| 앵커 | 초당 응답 수 (태그가 10 Hz면 약 10) |
| 공장 펌웨어 · 오류 · 뽑힘 | 무엇을 하면 되는지 안내 + 원시 로그 |

- **실제 거리**를 적으면 평균 오차와 기준선이 나온다
- **기록**: 조건(`los` / `nlos_car` / `nlos_body`)과 목표 개수를 정하고 시작 → `log_range.py`와 같은 CSV가 `data/range/`에 쌓인다
- **포트 놓기**: 포트는 한 프로그램만 잡을 수 있다. 펌웨어를 올리기 전에 누르고, 끝나면 '다시 잡기'.
  이 화면을 켜 둔 동안에는 `log_range.py`·`check_board.py`도 그 포트를 못 연다

### 터미널 도구

```bash
python3 tools/check_board.py                       # 연결된 보드 전부 재부팅시켜 부팅 메시지 확인
python3 tools/log_range.py --true 2.00 --cond los  # 태그로 300개 기록
python3 tools/analyze_range.py                     # data/range/ 전체 → 표
```

`log_range.py`는 1초마다 성공률 · 최근 평균 · 오차 · RX−FP를 보여준다. Ctrl+C로 멈춰도 그때까지 저장된다.

### 태그 출력 형식

```
# uwb_tag dev_id=deca0302 tx_ant_dly=16385 rx_ant_dly=16385 period_ms=100
R,ms,seq,dist_m,clk_ppm,C,F1,F2,F3,N,D      측정 성공
E,ms,seq,reason                             실패: timeout | rx_err | bad_frame
```

| 열 | 뜻 |
|---|---|
| `dist_m` | SS-TWR 거리 (클럭 오프셋 보정 후) |
| `clk_ppm` | 앵커 대비 태그 시계 오차 |
| `C`, `F1~F3`, `N` | 수신 진단 원시값 — 채널 세기, 첫 경로 진폭 3점, 누적 심볼 수 |
| `D` | DGC 이득 단계 (`DGC_DBG` 레지스터) |

진단값은 **원시값으로만** 보내고 dBm 환산은 [tools/uwb_proto.py](tools/uwb_proto.py)에서 한다.
틀렸으면 재업로드 없이 그 파일만 고치면 된다.

- F1~F3를 4로 나누는 것(소수부 2비트) — 포럼 보고. 첫 측정에서 RX−FP가 0.9 dB였는데, 나누지 않으면 −11 dB
  (직진파가 전체보다 셈 = 불가능)이 되므로 나누는 쪽이 맞다
- `DGC_DBG` 주소(이득 단계 D) — 매뉴얼 기준, 아직 검증 안 함

## 다룰 때 주의할 점

**보드**

| | 왜 |
|---|---|
| 실험 중 전원은 USB로. 핀으로 넣을 때는 5 V는 `5V` 핀, `3V3` 핀에는 3.3 V만 | 회로도상 USB 5 V → 다이오드 → `5V`(VDD5V) → 3.3 V 레귤레이터. `3V3` 핀에 5 V를 넣으면 ESP32·DW3000이 바로 상한다. 핀 이름은 기판 인쇄로 확인 |
| 금속 위(맥북 위·철제 책상·공구)에 올려놓지 않는다 | 뒷면 납땜이 닿아 합선된다. 금속은 안테나도 방해한다 |
| 만지기 전에 금속(문고리 등)을 한 번 짚는다. 모서리를 잡는다 | 맨 기판이라 정전기에 약하다. UWB 모듈·안테나는 손대지 않는다 |
| micro USB는 똑바로 뽑는다 | 가장 약한 부품. 휠체어·차에 달 때는 케이블을 테이프로 고정해 커넥터에 힘이 안 가게 |
| GPIO 4·18·19·23·27·34는 다른 데 쓰지 않는다 | 기판 안에서 DW3000이 쓰는 핀 |

**측정**

| | 왜 |
|---|---|
| **아직 공장 펌웨어인 보드는 꺼 둔다** | 공장 SIMPLE TX가 우리와 같은 설정(채널 5, 코드 9)으로 0.5초마다 신호를 쏜다 → 측정과 겹친다 |
| **앵커는 한 번에 1개만 켠다** (지금 펌웨어) | 짝 구분이 없어 앵커 여럿이 poll 하나에 동시에 답한다 ([원리 6절](UWB_원리_정리.md#와이파이-없이-어떻게-통신하나)) |
| 안테나 높이 같게, 방향 고정, 기준점은 안테나 중심 | [원리 2·4절](UWB_원리_정리.md) |
| 기록 중에는 보드에서 떨어지고 만지지 않는다 | 사람 몸이 반사·가림을 만든다. 0.41 m 기록에서 5초 평균이 6 cm 떠돌았다 |
| 0.5 m보다 가까운 거리는 기준으로 쓰지 않는다 | 책상 반사가 직진파와 섞이기 쉽다. 1 m 이상에서 재기 |
| 보조배터리로 앵커를 켤 때, 시간이 지나 실패가 늘면 배터리를 의심 | 보조배터리는 적은 전류만 쓰면 스스로 꺼지는 것이 많다 |

**맥 · 프로그램**

| | 왜 |
|---|---|
| 포트는 한 프로그램만 연다 | 화면(`live_view.py`)·Arduino 시리얼 모니터·업로드가 겹치면 실패. 업로드 전에 '포트 놓기' |
| 데이터가 끊기거나 `Invalid argument`가 나면 그 보드를 다시 꽂는다 | 맥 기본 CP2104 드라이버가 멈춘 것 (위 "맥에서 포트가 멈추는 문제") |
| 업로드가 중간에 끊기면 115200으로 다시 올린다 | 반쯤 써진 보드는 부팅하지 않는다 |
| 앵커·태그 펌웨어의 설정·안테나 지연값은 항상 짝으로 고친다 | 한쪽만 바뀌면 통신이 안 되거나 거리가 틀어진다 |
| 맥에 꽂힌 보드는 화면을 켤 때 재부팅된다 | 포트를 열면 리셋된다. 앵커가 맥에 꽂혀 있으면 몇 번의 실패가 정상 |

### 내구성 — 차·휠체어에 상시로 달 때

지금 보드는 **맨 기판 + 호환 모듈**이라 실내 실험용이다. 상시로 달려면 아래를 갖춰야 한다.

| 위험 | 무엇이 망가지나 | 대책 |
|---|---|---|
| **열** — 여름 차 안·대시보드는 70 °C를 넘기도 한다 | ESP32 모듈 등급이 −40~85 °C, DW3000 계열도 보통 같은 범위. 호환 모듈 "UWB-X3"는 등급 불명. 케이스 안은 자체 발열로 더 뜨겁다 | 햇빛 직사·대시보드 피하기. 밝은 색 케이스, 통풍 |
| **케이스 재질** | PLA는 약 60 °C에서 물러진다 → 여름 차에서 변형·처짐 | 3D 프린팅은 **PETG(약 80 °C) 이상, 실외는 ASA**(내열·자외선). **금속·탄소섬유·금속 도장 금지** — 전파를 막는다 |
| **진동** — 휠체어 주행, 차 문 여닫음 | micro USB 커넥터가 먼저 헐거워진다. 기판이 휘면 납땜 균열 | 모서리 구멍 4개로 나사+스페이서 고정. 케이블은 케이스에 묶어 커넥터에 힘이 안 가게. 상시 설치는 micro USB 대신 `5V`·`GND` 핀에 전선 납땜 + 열수축 |
| **물·먼지** — 주차장은 실외 | 기판 부식, 합선 | 방수 케이스(IP65 급) + 케이블 글랜드. 결로 대비로 케이스 안에 실리카겔 |
| **정전기** — 사람이 수시로 만지는 휠체어 | ESP32·DW3000 입출력 손상 | 플라스틱 케이스로 덮어 맨 기판이 손에 닿지 않게 |
| **전원** | 차 12 V는 시동 걸 때 전압이 크게 튄다(부하 덤프). 휠체어는 24 V. 보조배터리는 저전류에서 꺼진다 | 차량용·서지 보호가 있는 12 V→5 V 컨버터, 휠체어는 24 V→5 V 강압 컨버터. 앵커를 늘 켜 두면 차 배터리가 닳는다 → 시동·ACC 전원에 물리거나 저전력 대기(DW3000 sleep · ESP32 deep sleep)를 설계 |
| **안테나 주변** | 차체 금속에 붙이면 측정이 틀어지고 거리가 준다 | 안테나 쪽을 금속에서 몇 cm 띄우고 플라스틱 창으로. **케이스·브래킷을 단 상태로 안테나 지연을 다시 보정** (케이스도 지연을 바꾼다) |
| **부품 수급** | 4개 = 앵커 3 + 태그 1이면 예비가 없다. 호환품은 품질 편차가 있다 | 1~2개 예비 구매. 보드마다 라벨·보정값 기록 (보드 목록 표) |

## 실험 1 — 거리 정확도 (진행 전)

**목적** ±10 cm가 우리 환경에서 나오는지, 차체에 가리면 얼마나 나빠지는지.
앵커를 차 어디에 몇 개 둘지 정하기 전에 확인한다.

**절차** — 화면(`live_view.py`)의 '기록'이나 `log_range.py`로 기록한다
1. 앵커·태그 안테나를 **같은 높이**(휠체어 탑재 높이 근처)에 둔다. 높이가 다르면 측정이 길게 나온다 —
   1 m에서 높이차 0.3 m면 +4.4 cm ([원리 2절](UWB_원리_정리.md#2-위아래도-포함되나--그렇다))
2. 흰색 안테나끼리 마주 보게 하고 **방향을 바꾸지 않는다**(방향에 따라 안테나 지연이 달라진다). 주변 1 m에 금속 없이
3. 줄자는 **안테나 중심끼리** — 흰색 UWB 모듈에서 `◀ UWB4A` 스티커가 붙은 쪽 끝(금속 덮개 `UWB-X3`의 옆)이 안테나다.
   그 가운데에 펜으로 점을 찍어 두고 매번 그 점끼리 잰다. ESP32나 보드 모서리 기준으로 재면 그만큼(몇 cm) 틀린다
4. **LOS** 0.5 · 1 · 2 · 3 · 5 m — 거리마다 300개, 조건 `los`
5. **NLOS** 차체를 사이에 두고 2~3곳 — 휠체어가 차 뒤·옆에 있을 때를 가정, 조건 `nlos_car`
6. `analyze_range.py` 표를 아래에 붙인다. LOS 편향이 거리와 무관하게 일정하면 제시된 값으로 안테나 지연을 고치고 4를 다시

**덧붙일 것** (보드 3개 이상 준비되면)
- 보드별 안테나 지연: 보드 3개로 A–B, B–C, A–C를 같은 거리에서 재면 지연의 합 3개가 나오고, 거기서 보드 하나하나의 값을 푼다.
  앵커 여러 개로 위치를 낼 때는 쌍마다 값이 다르면 안 되므로 필요하다
- 안테나 방향 0° · 90° · 180°에서 같은 거리를 재서 방향 영향 크기 확인

**판단 기준**

| 볼 것 | 기준 | 정해지는 것 |
|---|---|---|
| LOS \|오차\|95 | 10 cm 이하 | UWB를 위치 측위에 쓸 수 있는가 |
| NLOS 성공률 · 편향 | — | 앵커 배치와 개수 |
| LOS·NLOS의 RX−FP 분포 | 겹치지 않는가 | 가려진 측정을 자동으로 걸러낼 수 있는가 |
